The new test-first checkpoint replaced those guard-success assertions with Source equality: 19 passed and five failed. The evidence is `artifacts/go-parity/query-loop-identity-red.log`. `SerialToolBatch` now retains name/ID identity as quoted JSON strings, comparing decoded JavaScript code units rather than Go's replacement-decoded strings. Available-registry lookup follows each tool's primary name or aliases in registry order. `LookupBackfillJSON` uses the same comparison; unknown names have no backfill. Observable backfill does not inspect an unrelated ID. `JSONToolCallContext`, `CallJSON`, `MapResultJSON` and explicit `JSONToolBatchCapabilities` retain raw IDs through hooks, permissions, progress, the handler and result mapping. Buffers handed to callbacks are copied: Source strings are immutable, so mutating a Go callback buffer cannot mutate later IDs or original history. The old scalar interfaces remain strict adapters and reject lone IDs before execution rather than substituting U+FFFD.

Unknown names generate Source's ordered shared-factory user message, including exact UTF-16 error text, original tool result ID and source assistant UUID, and continue the serial batch. The unparsed marker uses the actual Source one-own-key/raw-string/numeric-len predicate, a 200-code-unit preview, JavaScript number coercion and original property order. Marker feedback precedes registry and cancellation; malformed marker shapes remain ordinary unknown input. A known canceled tool uses explicitly resolved `withMemoryCorrectionHint` content; absence of that host value remains unsupported. There is no default empty hook or permissive permission implementation.

Deprecated lookup requires an explicit ordered `ToolDescriptor` catalog. A primary-name match blocks later catalog aliases but does not bypass availability; a deprecated alias needs its real `RegisteredTool` implementation. Missing catalog or handler fails explicitly. All builtin handler execution remains outside this proof.
