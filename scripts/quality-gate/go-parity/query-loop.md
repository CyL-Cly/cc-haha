# Independently built successful native-tool rounds

This corpus executes real `src/query.ts:225 query()`, `productionDeps()`, `queryModelWithStreaming`, the pinned Anthropic SDK and two private loopback HTTP responses. The Source registered tool is constructed from an **original** object/string schema declaration and original prompt literals shared before either renderer runs. Source uses real Zod, `runTools`, `runToolUse`, hooks, permissions, normalization and request construction. The `callModel` wrapper observes original history and final fetch arguments, then delegates to production and the real loopback socket.

Go receives original history/system strings, the original tool declaration, explicit runtime/device/session/query-source inputs and response wires. It never receives Source-rendered schema, prepared body, path, headers or a Source policy decision. Every round resolves an original `requestretry.Input`, using one `toolschema.Session` across rounds. `queryloop.RunControlled` delegates to the unique `modelyield.Run` → `requestretry.Open` path; that opener owns one `requestcontext.Prepare`, original environment authentication, client headers and physical creation attempts. The shared stream-history Controller consumes the returned stream once. The outer loop no longer accepts prepared requests or contains its own raw stream consumer. Original assistant envelopes enter the next history; display backfill never replaces them.

Production `SerialToolBatch` now owns the portable successful serial steps previously implemented in the fixture: raw code-unit registry lookup/aliases; serial partition checks; exact unknown/unparsed/canceled-tool feedback; original schema parsing again at execution; optional tool value validation; backfill of a shallow input clone; resolved hook/permission input convergence; restoration of the model's original string `file_path`; original tool call; one result mapping; small-result processing; shared-factory allocation/defaults with Source property enumeration; context modifier before emission; and in-progress completion after emission. `ToolCallContext` exposes resolved pre-response history, query tracking, the original assistant envelope and opaque host state. Concurrent calls, MCP/Bash-specific policies, validation feedback, non-allow permission feedback, large-result persistence and call-error feedback stop explicitly. These failures are unsupported boundaries, not counterfeit Source errors.

Permission and hook **policy** remains external. The batch requires `PreTool`, `ResolvePermission`, `PostTool` and `InProgress`; the loop requires preflight, original context resolution, request dependencies, post-sampling, StopFailure, abort cleanup, ordinary stop and post-tool-pause capabilities. Missing capabilities never imply permission, identity compaction or empty hooks. The fixture supplies an explicit no-managed-policy, no-hook/compaction snapshot and a permission callback that records input and either allows it or returns a declared fresh path/content override. Its private registered file handler does not implement the production Write tool's filesystem behavior.

`CreateOrderedUserMessage` moves the Source factory enumeration adapter into production while reusing the shared factory's defaults and UUID/time behavior. `ProcessSmallTextToolResult` uses JavaScript UTF-16 length/whitespace and corrects empty text/arrays with Source's completion marker. Small text and tool-reference arrays are supported; media, structured and persisted results remain separate boundaries. `NormalizeOrdinaryToolResult` ports release-default per-result user normalization with tool search disabled: display-only progress/system/virtual records are discarded, and nested tool references are stripped from an ordered copy without mutating observable output. Local commands, attachments and media fail explicitly. Full history merging/pairing remains with requestcontext.

The original 12 actual query scenarios cover interactive `repl_main_thread` and headless `sdk`: added, overwritten or absent backfill; reordered schema input with unknown UTF-16 property names; fresh permission input changing path or content; empty-result correction; and nested tool-reference stripping. Every first response repeats tool IDs and block-stop events and ends with `end_turn`. It must execute one private file side effect exactly once and make exactly two requests. Source execution-time Zod parsing strips unknown fields and follows declaration order, while ordinary registered-tool request normalization retains the **original** assistant input, ordering and unknown fields. Both behaviors are tested independently. The original prompt callback must run exactly once across both requests, proving use of the retained session cache.

Traces compare complete request body/path as exact strings, every explicitly resolved pre-fetch header, original model-history and final-history message bytes, yields immediately and after live updates, UUID/time allocation order, prompt/permission/backfill/in-progress/tool effects, execution count, private file content and terminal result. Each resolved header/body/path is also checked against the actual loopback socket. Automatic Bun versus net/http transport headers remain side-specific raw metadata and are not claimed equal. Only the outer observation record uses canonical key comparison; embedded request/message strings are never normalized.

Test-first evidence: after prepared-request injection was removed, the old Go candidate failed because it still required captured requests. Independent builder/batch integration closes that failure. `backend/internal/queryloop/testdata/source_contract.json` contains 22 actual Source recordings with original inputs/wires for native tests. Native expectations are never generated from Go. Eleven original comparator mutations alter native schema, second request body/path, credentials, history/yield/allocation order, side-effect order/count or file content and must be rejected.

Source import guards validate disposable HOME/config/cwd before production imports. Observable adapters return null for the external secure store and absent data for the exact managed-policy paths; they block external filesystem/native/network access and grant only the parent's exact loopback origin. Tests require `blocked=[]`, the exact secure read and five absent managed-policy filesystem operations. Five Source tripwire/sentinel negatives and five Go negatives reject missing/public origin, missing profile, mismatched HOME or prepared-request shortcuts before request construction/tool execution. Go builds use the pinned runtime, verified offline seed and private build HOME/cache.

Focused verification now consists of 56 `query-loop.test.ts` tests: 22 Source self replays, 22 Go differential profiles, 10 guard negatives, the original 11-mutant gate and an eight-mutant raw identity gate. The prior independent tool-free `query-request.test.ts` has 17 tests. Native queryloop race/vet and statement/changed-executable-line coverage evidence is recorded separately in ignored `artifacts/query-loop-native/`.

The separate `query-loop-identity.test.ts` compares 22 actual Source `runTools` profiles against Go, including unknown feedback, legal lone-ID execution, marker precedence, deprecated scalar catalog validation and known cancellation. Raw quoted UTF-16 identity now survives lookup, context, progress, mapper, user feedback and the independently built next request. Ordinary scalar callbacks remain strict adapters. See `query-loop-identity.md` for exact scope, Source ordering and test-first evidence. Stream-history's raw code-unit ID deduplication remains unchanged.

This proves the bounded independent successful native-tool round composition. It does not establish production tool handlers, general Zod/error feedback, arbitrary nested JavaScript reference/prototype mutation, non-string file-path convergence, progress streaming, concurrent execution, complete permission/hook policy, reactive compaction, retry/fallback/tombstone/attempt feedback, max-turn attachments, OAuth/cloud routing, media, persistence, CLI/TUI/Electron integration or the complete Agent benchmark. The execution profile uses a scalar registry, arbitrary model UTF-16 **string** identities and plain-object backfill; arbitrary lone-code-unit registry definitions and non-string identities remain unsupported. No unsupported branch falls back to TypeScript or permissive Go policy.

The shared-opener integration preserves all 22 actual two-round Source goldens and the three tool-free goldens without updating expectations. Controlled consumer stops accept an assistant or normalized tool result only after the yield resumes; already accepted history survives a later stop. PostSampling enters synchronously and its host can report an unimplemented capability; its background completion is separate. The last original Record isApiErrorMessage chooses StopFailure, and output-limit recovery remains an explicit boundary. Literal submit interruption and other cancellation causes remain distinct. Native terminal/control tests do not certify full production preflight, active hooks, tool-cancellation result generation, QueryEngine writer/cache finally or SDK output. Those host services still need actual outer-query integration.
