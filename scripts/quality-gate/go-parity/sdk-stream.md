# Pinned SDK raw stream contract

`sdk-stream.fixture.ts` imports the installed Anthropic SDK and its actual
`Stream.fromSSEResponse` after the disposable-home guard and capability guard.
The fixture checks the SDK's exported version is `0.80.0` and the child runtime
is Bun `1.3.14`. HTTP status profiles call the actual
`client.messages.create(...).withResponse()` with `maxRetries: 0`; this includes
the client's HTTP APIError generation rather than applying a stream decoder to
a response the client would reject.

The loopback server writes a fixed HTTP/1.1 wire, including deterministic Date,
Content-Length and explicit Connection headers. A streamed `Bun.serve` Response
was unsuitable as the reference fixture server: it could choose chunked
framing or omit empty headers before the client received them. The Go test
adapter writes the same fixed wire and calls production `OpenMessagesStream`.
Neither fixture substitutes SDK dispatch, JSON parsing or error construction.

The current supported corpus covers six Messages event names, legacy
completion, event/body mismatches, ignored ping/unknown/empty events, arbitrary
JSON values, invalid JSON diagnostics, full SSE/HTTP error payloads, field order,
duplicate keys, nonfinite doubles, negative zero, UTF-16, replacement UTF-8, BOM,
SSE separators and EOF. A singleton array nested 10001 times tests raw dispatch
beyond `encoding/json`'s depth limit; its Go observation deliberately verifies
that exact raw singleton shape without feeding it back through that validator.
Deep SSE and HTTP error objects also select a shallow message around a deeply
nested future field, including repeated and escaped top-level property names,
selected object/nonfinite messages, and falsy-message full-payload fallback.
Their complete payload stringify remains strict; only the explicit future
singleton shape is compressed for the fixture's numeric-leaf path observation.
These cases do not establish every deep object or Controller behavior.

Error comparisons retain class, name, exact message, payload, status and request
ID ownership (undefined versus null), full observed headers, and the SDK's two
logger diagnostics. Number leaves are observed before JSON.stringify so an
Infinity, negative zero or rounded integer cannot disappear behind identical
serialized JSON. The native source golden comparator also retains UTF-16
strings instead of decoding lone surrogates into replacement characters.
Language-specific Error stacks are outside this typed stream profile.

Actual Bun fetch response parsing differs from constructing WHATWG Headers.
Empty and ASCII-whitespace-only header values are discarded. The corpus fixes
duplicate behavior for request-id, x-future, content-type, set-cookie and twelve
common response-header names. Set-Cookie remains multiple iterator entries;
other tested names use either comma-space combination or the last nonempty
value. Go's production header adapter rejects an unproved duplicate header
instead of choosing a rule silently. The explicit Connection-close profile is
**known pending**: Go net/http discards its original header. Its test requires a
strict comparison failure and writes both observations to
`artifacts/go-parity/sdk-stream-pending/`. That passing negative test records an
incompatibility; it is not an equivalent profile or a waived comparison.

Every child receives a private HOME/config/current directory and explicit
`--no-env-file`. Only its allocated HTTP loopback origin is granted to fetch,
with redirects refused. Filesystem, subprocess and native credential
capabilities are denied; direct SDK observations require blocked, secure-store
reads and managed-policy reads all to remain empty. Go compilation uses the
shared offline dependency seed and private caches. No provider quota is used.

The committed `backend/internal/provider/testdata/sdk_stream_contract.json`
contains actual SDK observations, not expectations generated by the Go
implementation. Source self-replay, deliberate comparator mutations and
Source/Go comparisons must pass separately. Generated observations are ignored
artifacts. These tests do not prove query orchestration, tool commit/retry,
stream disconnect/cancellation, tee/consumption ownership, gzip/chunked HTTP
metadata, unknown duplicate headers, full CLI handlers or Benchmark scores.
