# CLI editable settings parser/writer — finite release boundary

This component ports the actual CLI settings consumer, independently of the desktop settings service. It is available as a Go service, and is not connected to normal CLI main/init or a version-11 migration dispatcher.

## Production API and profile

`backend/internal/clisettings` retains its existing `State`: session/per-source/path caches, plugin base and internal-write marks. `NewService(Options)` requires an explicit state, absolute config home/original cwd, positive PID, clock and `ExternalReleaseProfile`. This profile means the shipped TRANSCRIPT_CLASSIFIER feature is on, USER_TYPE is external, XAA/other inactive release features and cowork are off. The service does not infer these values from process environment or read credentials.

- `ParseFile(originalPath) (*ParsedSettings, error)` keeps the original cache key, caches null/I/O failures, clones validated ordered JSON on every return, and retains a shared errors-array reference. `Errors` is the legacy read slice view. Consumers that mutate or retain a growing array use `ErrorReference() *[]json.RawMessage`; copying a Go slice header does not provide JavaScript array identity. Actual Source `errors.push` and earlier observation aliases are covered.
- `GetEditableSource(source, projectOverride)` preserves direct per-source cache identity when no override is supplied; override bypasses that cache. The parsed path cache remains active. Returned settings are ordered/raw UTF-16 JSON rather than an encoding/json map.
- `UpdateEditableSource(source, projectOverride, Patch{Object, UndefinedPaths}) (WriteResult, error)` accepts original ordered patch JSON plus explicitly quoted UTF-16 undefined paths. Actual Source returned failures are `WriteResult.Error`; an unimplemented capability is a separate `*CapabilityError` and must propagate rather than be turned into a successful fallback.
- `Path` selects normal user `settings.json` and project `.claude/settings.json`. Local gitignore/cowork/managed source reads remain unsupported. Policy/flag writes retain their specific Source read-only exits. They are not a generic no-op initializer.
- `FileSystem` supplies real synchronous read/stat/resolve/write-flush/chmod/rename/remove operations; `OSFileSystem` writes and fsyncs actual files. `Observe` exposes mark/reset and physical operation attempts. It does not replace the writer. Clock/PID are explicit host inputs; the clock is the same integer-millisecond Date.now source used by State and physical temp naming. Returned mutable references require caller synchronization.

## Supported parsing and behavior

The independent literal classifier enumerates all **86 active top-level release keys**. Supported branches are `model`, `env` and external `effortLevel` (low/medium/high; invalid input catches to own undefined). Genuinely unknown ordered JSON is retained, including inactive release keys, distinct lone UTF-16 keys/strings, duplicate/integer property order, negative zero and numbers outside double precision. All other active known keys are capability errors, including invalid values; they never become unvalidated unknown passthrough. This is not a full schema for any of the 13 field families.

`env` calls `protocol.ExactJavaScriptStringJSON`, preserving UTF-16 and propagating conversion failures. Its consumer projects those failures to the actual supported Zod invalid-type diagnostics. Objects with noncallable own `toString`, and arrays containing them, can fail. Numeric overflow stays a number until coercion (`1e400` yields env string `Infinity`) or final stringify (unknown numeric overflow becomes null). Known schema fields are emitted in Source order before unknown fields. The only admitted invalid-known fallback is exact `hooks:123`, with its actual record-type validation diagnostic and hooks suggestion/doc link. Valid/unimplemented hooks are rejected.

Files use actual UTF-8 replacement decoding or UTF-16LE BOM decoding, preserve literal lone UTF-16 units through the JSON source seam, strip one leading BOM for parse, and normalize CRLF. Empty JavaScript-trimmed content yields an empty object; malformed JSON and valid null remain validation failures. Canonical read paths use NFC while cache keys retain the original path. Special files/UNC, prototype-named merge graphs, raw scalar/array merge targets and object-source/array-target merges are explicitly unsupported; those capabilities are not claimed Source-equivalent behavior.

The writer clones validated path-cache data before merging, bypasses the per-source cache, rereads uncached raw JSON on a real validation failure, recursively merges ordinary JSON objects, replaces source arrays and applies own-undefined deletion. An externally changed file can be overwritten by a warmed old path cache; this actual Source behavior is preserved. A successful write marks first, temp-flushes/fsyncs, preserves existing mode, renames, then resets the three caches. A temp/chmod/rename failure cleans up and uses direct flush fallback. A final failure leaves the mark and caches intact. Existing relative/absolute file symlinks are preserved and their target is written. No settings-file lock, desktop recovery, backup restore or repository format marker is introduced.
