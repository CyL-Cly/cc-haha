# CLI pre-trust settings/environment and extra-CA component

This component ports the actual exports `applySafeConfigEnvironmentVariables` and `applyExtraCACertsFromConfig` for an explicit external release profile. It is not CLI init, normal command dispatch or the post-trust environment/transport setup. Production lives in `backend/internal/clistartupenv`, depends on the real `cliglobalconfig` and finite `clisettings` services, and does not read process-global OS environment or change `os.Setenv`.

## Production contract

`NewEnvironment(original protocol.JSONObject)` retains Bun 1.3.14's scalar JavaScript property view: quoted UTF-16 keys, insertion/numeric-key enumeration order, own undefined (nil), null, boolean, string, doubles, Infinity and negative zero. `Get`, `Snapshot`, `SetProperty` and `Assign` preserve raw values and earlier assignments before a later capability failure. The environment is a session-owned, serial-access object; arrays, objects, getters, prototype mutations and mutable aliases are explicitly unsupported. This is not a native process-spawn environment serializer. In particular it does not stringify arbitrary assigned values as Node's environment setter would.

`New(Options)` requires real enabled global/settings services, shared settings state, the original environment, absolute config HOME and `Host.Profile=EmptyPolicyReleaseProfile`. The host explicitly declares remote cache, MDM/HKCU cache, both system policy files and plugin base absent. A preexisting plugin cache contradicts that snapshot and fails. `AllowedSources` is the original setting-source list (nil means default, empty means isolation); policy and flag are still always enabled, with JavaScript Set ordering. `FlagPath` and `FlagInline` are original inputs, not Source merged output. Inline settings go through the real finite schema validator.

`ApplySafeConfigEnvironmentVariables` independently executes the original order: capture CCD spawn keys once; global env; enabled user and flag settings; actual cc-haha settings bytes and providers-absence reads; remote eligibility; policy; fully merged settings' safe-key projection. It applies the original SSH, host provider, internal/team and CCD filters at each source's current environment, rather than freezing flags at the beginning. Provider and safe key lists are literal Source recipes. The merged session cache retains the whole supported/unknown settings object, ordered nested JSON, array concatenation/Set identity and catch-produced own undefined. Existing real parsed/source/session caches provide stale-until-reset behavior. Flag/user paths are deduplicated at the merged disk-load boundary, while each trusted source retains its original separate behavior.

`ApplyExtraCACertsFromConfig` has the original truthy early return before reads. It reads global then user settings directly even when user settings are disabled in settingSources, ignores project settings, selects user CA or global CA, and records original UTF-16 debug text in order. The selected scalar remains a raw environment value; only debug interpolation uses the exact JavaScript String helper. Ordinary global read errors produce the original caught debug path. Unimplemented settings/host capabilities fail explicitly rather than being swallowed as a successfully migrated source.

The remote eligibility profile requires the actual initial `CLAUDE_CODE_LOCAL_SKIP_REMOTE_PREFETCH='1'` early-return path; that false result is cached even if the flag changes later. Other provider/auth eligibility paths fail. The cc-haha providers index must actually be absent at both original read points; present, unreadable or unported provider/proxy behavior fails. The existing DeepSeek legacy compatibility recipe is independently ported. Original cc-haha bytes use the JavaScript UTF-8 replacement decoder and JSON semantics; invalid JSON retains the original empty fallback.

Filesystem/schema host controls (`HOME`, `CLAUDE_CONFIG_DIR`, `USER_TYPE`, `CLAUDE_CODE_ENABLE_XAA`, `CLAUDE_CODE_SIMPLE`) are frozen explicit capabilities. A settings assignment changing one fails before that assignment, retaining any earlier admitted assignments; a caller changing one causes the next export to fail. Internal USER_TYPE is unsupported. This guard prevents fixed Go services from silently reading the wrong filesystem/schema after a raw environment mutation. It is not a claim that the original Source rejects those mutations. The adapter must be expanded and tested before those profiles can enter normal startup.

## Actual Source oracle and comparison

The fixture imports the actual exports only after disposable HOME/config assertions and observable native/network/FS denial capabilities. It uses real global/config enablement, bootstrap original CWD/source/flag state, original settings parser/cache/merge and actual Source functions. No init callback, handwritten Source algorithm, business-class mock or Source-rendered environment is supplied to Go. Original file strings/base64, original raw environment and neutral operations are the common inputs.

Logical settings reads are observed at the real `fileRead.readFileSync` export, which delegates the original encoding-aware reader. Global/cc-haha/providers reads are observed at the real native read export. These ordered operations are not a claim that Bun and Go perform identical lower-level filesystem syscalls. Actual assignments delegate original Object.assign; extra-CA debug observation delegates the real sink. Comparison includes exact quoted UTF-16 environment keys and values, own presence, original numeric kind/String/finite/negative-zero facts, complete ordered merged settings bytes, recursively typed session cache, validation errors, logical reads, assignment contents and CA diagnostic order. Plain JSON alone would hide negative zero and Infinity; typed observations intentionally retain them. Only allocated HOME is replaced in comparison after raw evidence is saved.
