# Independent request construction

`backend/internal/requestcontext.Build(Context, Dependencies)` constructs a request
from original message envelopes, system strings, thinking/options, and an explicit
host snapshot. It does not accept Source request bytes, a Source-selected path, or
Source-normalized API messages. Its `Result.PreparedRequest` is the existing
provider request type and can enter `OpenMessagesStream`. `Result.Params`,
`NormalizedHistory`, `BudgetSource`, and `PreviousRequestID` expose the construction
boundary for a controller or query-loop host.

The declared host profile is
`requestcontext.DirectRelayProfile` (`direct-relay-release-default-no-experiments`).
The host supplies device/session identity, workload, SDK betas, cache TTL eligibility
and allowlist, and only the environment names allowed by `checkProfile`. These are
session/config inputs rather than a captured request. There is no ambient home,
filesystem, credential, or environment read in the Go builder. UUID allocation and
time come through `Dependencies`.

`Prepare(Context, Dependencies)` now performs native schema rendering, history
normalization/pairing, ID allocation and original system-block construction once
per query. Its `PreparedContext.BuildAttempt(AttemptOptions)` rebuilds request
params, signed body and budget provenance for each creation retry; `Build` is a
single-attempt compatibility wrapper. `NormalizedHistory()` exposes an observation
snapshot immediately after preparation, before the scheduler checks an already
aborted caller, without constructing a counterfeit attempt.

The retry model never replaces the original `Options.Model` in this declared
profile. Source captures the request model, thinking capabilities/default limits,
effort, system and tool schemas from the original options. A truthy retry output
cap overrides the original option cap, adjusts optional thinking and marks the
budget explicit; zero/NaN do not override it. Original `[1m]` betas remain frozen.
The no-experiments profile excludes the dynamic Sonnet experiment and the
model-specific caching environment gates. The wire CCH signature legitimately
changes with the retry body: frozen system blocks are compared before that signing
boundary, and each resulting signed request is compared separately.

The 89 original-input Source goldens also execute three BuildAttempt calls from
one independent Go Prepare, with exact signed bodies and allocation counts.
Native tests exercise original native-schema host resolution, one-time schema
generation, retry output caps/thinking/provenance, missing preparation and observer
snapshot isolation. The real creation-retry oracle records actual
`queryModelWithStreaming` pairing once plus per-request allocation counts; its
contract is described separately in `request-retry.md`.

## Actual Source boundary

The oracle calls production `queryModelWithStreaming` in
`src/services/api/claude.ts`. In particular it exercises `paramsFromContext`,
`normalizeMessagesForAPI`, `ensureToolResultPairing`, cache breakpoints, metadata,
model output limits, system prompt splitting, attribution/fingerprint, effort,
thinking, extra-body spread, and actual pinned Anthropic SDK 0.80.0 request creation.
Relevant production callers also include `src/utils/messages.ts`,
`src/utils/context.ts`, `src/utils/model/model.ts`, `src/utils/api.ts`, and
`src/utils/fingerprint.ts`.

The Source observer delegates both pairing and API logging to their production
functions. It captures the resulting API-message JSON bytes and previous original
assistant request ID. A final-fetch observer delegates actual fetch to a private
loopback server; it records the complete resolved application/SDK header set,
method, path/query, and signed body bytes. Source history before/after and UUID
allocation counts are compared strictly. No recursive key sorting or terminal
replacement normalization is applied to body or history strings.

Go starts from the same original envelope/system JSON sources and context inputs.
It independently normalizes and pairs history, maps cache breakpoints, builds
params, and invokes existing `provider.PrepareBetaMessages`. The fixture then
independently resolves client options and sends the resulting request through the
production raw stream provider to another loopback server. It verifies the actual
wire body/path and every resolved application header against the final-fetch
observation. The native golden JSON was captured from actual Source observations,
not generated by the Go implementation.

Both transports' full automatic HTTP header sets remain recorded independently in
`sourceOnly.wireRequests` and `goOnly.wireRequests`. Bun fetch and Go net/http
automatic headers are not claimed equivalent. Response yields, last-main-request
ID, capability observations, and Source runtime/SDK identity are Source-only
evidence; they are not counted as Go response-controller behavior. Native goldens
explicitly freeze the captured Bun platform/architecture/version for SDK wire
identity instead of pretending a Linux Go process is Bun on Linux.

## Supported profile and explicit stops

The corpus covers direct custom relay requests with fixed release-default model
capabilities, empty native tools, text/thinking/local tool-use/result history,
supported normalization/repair, headless and interactive system prefixes, prompt
cache/TTL snapshots, explicit/default budget provenance, metadata overrides,
manual/required adaptive thinking, opt-in effort/output format, SDK/explicit betas,
extra tool schemas/tool choice, ordered extra-body fields, numeric stringify, and
UTF-16 string/property-name preservation. It includes the original `deepseek-flash`
model ID and the existing local proxy base-path profile; these use loopback and do
not establish live endpoint support. `ExtraToolSchemas` is an actual separate
Source context option; it is not a replacement for native tool registration,
permissions, or execution.

Unported inputs return `*requestcontext.CapabilityError` before transport. They
include undeclared host profiles, unknown environment/config controls, native
tools/permission callbacks, first-party/internal/cloud auth profiles, dynamic model
catalog/capability overrides, attachments/media and synthetic API-error anchors,
local command messages, malformed/nested unsupported blocks, malformed extra
metadata Source exceptions, unsupported thinking modes, and non-object
`output_config` spreads. Imported envelopes whose retained properties are identical
but ordered provenance differs also stop explicitly; a UUID is not treated as an
unconditional unique provenance key.

The profile does not migrate experiments or session latch resolution, OAuth/cloud
client branches, media/error recovery normalization, native tool schema callbacks,
the complete CLI handlers/TUI, server lifecycle, tool execution, multi-round query
orchestration, retries, or compaction. It constructs from caller-provided latch
snapshots. It has no production-entrypoint cutover and is not evidence of unchanged
live Benchmark scores.

## Deterministic evidence

The focused corpus has 89 actual Source self/self cases and 89 independent Go
cases, five intentional comparator mutations (body, header, path, history, UUID),
and six pre-import isolation rejections (home, allocation root, symlink,
environment override, network, native process). Source production imports follow
the disposable-home guard and capability installation. The only external managed
settings paths are explicit absent adapters; native secure-store reads are
observable null adapters. Every successful Source child asserts no blocked
capability use and the exact absent-policy reads. Test homes/build caches are
private, Go dependency hydration is offline, and checks use no live model or saved
credentials.

Actual differential failures were retained before fixes: malformed fixture system
input decoding; invalid/numeric effort precedence; and Opus 4.6's actual Source
canonicalizer resolving to Opus 4's 32k limit. Go preserves that pinned Source
behavior. The first native golden comparison also exposed an observation-only
distinction between nil Go `RawMessage` and Source's explicit absent-ID `null`;
the observer now materializes null without changing `Build`, body, or expected
data. No failing expected body was copied into the builder.

The final focused run is 189 passed, 0 failed, and 9,961 assertions: 89 Source
self/self cases, 89 independent Go cases, five comparator mutations, and six
guards. The DeepSeek profile first passed Source self replay while Go rejected its
unmigrated model ID, then passed both implementations after the explicit model
profile was added. It freezes `model: "deepseek-flash"`, `max_tokens: 32000`, and
`/proxy/providers/fixture/v1/messages?beta=true`.

Native tests additionally load three self-replayed actual Source effort-env
goldens (`auto`, whitespace/case-normalized `LOW`, and `max`). The final
darwin/arm64 package unit and race runs each have 122 passed tests, 0 failures,
and one skipped private parity entry. Build, vet, and nonmutating formatting pass;
statement coverage is 94.7%. The unchanged 90% changed executable-line evaluator
initially rejected 736/830 (88.67%). After meaningful Source-observed regressions
and explicit rejection-diagnostic assertions it passes 747/830 (90.00%). That is
the package's aggregate changed-line gate, not a claim that every individual file
exceeds 90%. Other native targets and the complete corpus are parent-owned checks.

Ignored evidence is under `artifacts/go-parity/request-context-source`,
`request-context-go`, `request-context-native-source`, and
`request-context-native`. The focused package run does not itself provide a whole
repository before/after manifest; the integrated parent lane supplies that gate.
