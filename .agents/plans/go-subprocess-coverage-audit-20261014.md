# Subprocess coverage collection — read-only audit, 2026-10-14

No collector, test runner, production source, threshold or exclusion was changed. This audit identifies a real collection gap; it does not assign coverage credit to an uninstrumented execution.

The official unit command in `scripts/pr/run-go-tests.ts:467` instruments `./...` plus both controlled forks and records the `go test` profile. It does not ingest Go parity `.cover` artifacts. Tests that separately run `go build` compile uninstrumented production binaries unless they explicitly add `-cover`; parent `go test -coverpkg` does not propagate instrumentation into a new build. Tests that re-execute their instrumented own binary can lose counters if their explicit private subprocess environment drops `GOCOVERDIR` or they omit the appropriate test-binary output flag.

Static current-tree inventory found **40 Go unit-test files** with explicit `exec.Command(... "build" ...)` sites, **36 files** re-executing `os.Executable()`, and **59 Go parity TypeScript files** compiling Go executables/test binaries. This is a build-site inventory, not a count of exclusive consumer functions or covered lines. Examples include public CLI auth/resume/model/doctor/MCP/plugins/file operations, public TUI exit/history, tmux pane workers, and PTY command/config/workflow/media/keybinding helpers. Twenty-two same-binary examples are in application. The child explicitly receives disposable HOME/config/TMP, but public PTY wrappers such as `keybindings_pty_test.go:40` and `tui_panels_pty_test.go` do not forward the parent's coverage directory.

Three parity wrappers already compile with `-coverpkg`: `stream-abort.test.ts`, `model-yield.test.ts`, `https-request.test.ts`. They request `-test.coverprofile` and save `.cover` artifacts beside actual Source/physical transport receipts. Those artifacts are not read by the official `runGoChecks` unit coverage calculation. Most other parity wrappers use ordinary `go build` or `go test -c`, including protocol/provider, query request, session recovery/resume, settings and desktop HTTP fixtures. `prepareGoBackend` for actual Agent E2E also builds the full production CLI without coverage.

The current failed checkpoint02 partial profile shows `main_print.go` **547 / 1,205** executable lines missing and `sdkhost/host.go` **428 / 1,212** missing. Public subprocesses actually construct/start these same components, so instrumentation can capture missing branch executions. The static audit cannot honestly say how many of the **975** lines are hit only in subprocesses: many methods also have in-process unit callers, and a reachable branch is not a recorded hit. A private instrumented replay is required to quantify the newly covered union. The rest of core's debt has the same limitation; a numerical claim that collection alone will reach 90% is unsupported.

The installed Go 1.25.7 source confirms the intended mechanism. `cmd/go/internal/test/test.go:1567–1582` gives test binaries both `-test.gocoverdir` and `GOCOVERDIR`, explicitly to support tests building subprocess tools. `testing/internal/testdeps/deps.go:225` creates/removes its own temporary directory when an independently invoked test binary has no `-test.gocoverdir`; a re-executed helper must deliberately retain its private output directory. `internal/coverage/cfile/emit.go` emits normal covered application binaries' data into `GOCOVERDIR`. Existing `sdkhost/public_print.go:279` deliberately retains this tooling variable outside provider request options, with a regression test, so it is already a recognized process-only boundary.

The next concrete experiment is an unchanged-source private snapshot of public `tui_exit_public_pty` or CLI MCP/file operations, plus a same-binary panels/keybindings helper and one existing held-HTTPS parity profile. Build actual production CLI with `go build -cover -covermode=atomic -coverpkg=<the exact current approved production/fork package inventory>` and retain a private `GOCOVERDIR` for every real child. For instrumented test-binary children, pass a private `-test.gocoverdir`/`-test.coverprofile` receipt instead of assuming inherited environment alone is sufficient. Run original deterministic assertions unchanged, require successful normal completion and real counter files, then use the toolchain's `go tool covdata textfmt`/merge to produce the physical profile.

Admission must check exact source SHA-256 against the same candidate snapshot (including fixture/oracle/lock inputs), native GOOS/GOARCH/toolchain/build tags, approved controlled replacement identities, declared cover package scope and atomic mode. Reject stale/mixed-source, foreign target, unsupported namespace, missing counter metadata or failed product runs. Merge covered executable sets only; no fabricated counters, scaling, zeroing denominators or changing thresholds. Preserve all original unit hits and include the full existing changed-line scope. Report the newly hit union before deciding whether/how to integrate collection. This analysis does not authorize a collector implementation or equate build-only/parity-only evidence with the final full gate.
