## 从目标推导工作，而不是从代码量推导进度

用户需要的结果是：**打开桌面应用就运行 Go；CLI、TUI、Web UI 都能通过正常对话完成原来支持的任务；原有会话可以继续；Agent Harness 的评测行为没有回归。** React 保留。

由此得到五个完成条件：

1. **能力完整。** 原版发行中支持的入口、工具和任务都有可执行的 Go 实现，正常启动无需额外指定工具子集或关闭未迁移功能。
2. **行为等价。** 相同初始状态下，模型可见的 Prompt、上下文、工具 schema、参数、权限、预算、错误和副作用语义保持一致。界面与传输方式可以不同，但不能产生不同的任务结果或执行权限。
3. **状态可靠。** 完成、停止、断线、崩溃和重启后，会话、模型选择、权限和任务状态仍正确；不会丢数据或重复执行已完成的副作用。
4. **实际可交付。** 验收的是安装候选中的真实 Electron 窗口、Go 二进制和公开 CLI，而不仅是源码入口、开发页面或交叉编译产物。生产启动链不调用旧 TS CLI/Server/Harness。
5. **证据可重复。** 确定性差分证明契约，真实模型任务证明正常使用链路，配对 Benchmark 检查评测回归。三者分别记录，并绑定被测候选。

迁移保持原产品语义；行为优化另外处理。有限在线采样不能保证随机模型每轮回答或得分完全相同，因此必须保持评分条件不变，预先冻结统计判定，并在证据不足时保留“未验收”。
