# Native Ultracode interactive state and Workflow authorization

## Scope and original producers

This batch connects ordinary interactive sessions to the existing shared Go MainPrint/SDK Harness. It does not create another Agent runner or change generic owner admission. All evidence here uses temporary homes, fake keys, original Source through pinned Bun 1.3.14, and private loopback peers. No real model, account, desktop profile, or external recipient was used by this batch. Signed desktop/live model verification belongs to the root integration task.

Original contracts read and exercised:

- `src/main.tsx`: literal `--effort ultracode` resolves to `xhigh` with a separate AppState flag. The CLI flag does not run the interactive model eligibility check.
- `src/state/AppStateStore.ts`: Ultracode is session state; keyword suppression is per prompt. Neither is persisted as standing consent.
- `src/tools/WorkflowTool/WorkflowTool.ts`: bypass and noninteractive allow first; interactive Ultracode allows; otherwise retain machine/named permission checks and the ordinary ask decision.
- `src/commands/effort/effort.tsx`, `src/utils/effort.ts`, and `src/utils/workflows/ultracode.ts`: `/effort ultracode` needs enabled Workflows and an xhigh-capable selected model; successful ordinary effort changes clear standing Ultracode. Low/medium/high persist, external xhigh/max remain session-only, and auto removes the setting. Environment precedence and original refusal/warning messages remain intact.
- `src/utils/workflows/keyword.ts`, `enabled.ts`, and `src/components/PromptInput/PromptInput.tsx`: conservative closed literal spans, JS word boundaries and UTF-16 offsets, interactive/settings gates, and `chat:workflowKeywordToggle` (`meta+w`) with the original five-second notice. Suppression affects the submitted prompt and resets when its keyword disappears or its composer is cleared.
- `src/utils/attachments.ts` and `src/utils/messages.ts`: input keyword attachment, round Ultracode enter/full, enter/short, and exit transitions use the original reminder text and order. SIMPLE/disabled attachments and child/main-thread boundaries remain effective. Keyword opt-in is a turn attachment and does not grant persistent Workflow permission.
- `src/utils/sessionStorage.ts:isLoggableMessage`: external transcript filtering removes these raw attachments. Actual cold resume does not revive standing consent or invent an exit instruction from an attachment absent on disk.
- `src/utils/tasks.ts`, TaskCreate/TodoWrite tools, and `src/utils/fileHistory.ts`: the same interactive bootstrap state selects TaskV2 versus TodoWrite and enables interactive Notebook checkpoints from live `fileCheckpointingEnabled !== false`; SDK callers retain explicit checkpoint opt-in and global environment disablement.
